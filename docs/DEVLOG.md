## v0.0.33（2026-09-30 打包，2026-10-14 确认上架）· 用药提醒与安全加固专项

**已上架飞牛应用中心**（tag `v0.0.33` → `904d80e`；fpk 13,654,755 B / sha256 `81fadec9…`），
结束了 0.0.27 之后连续五个版本只进 GitHub Release、不上应用中心的状态。各版累计改动详见下方各段与 CHANGELOG。

- **用药与补充：医嘱计划 + 打卡 + 到点提醒** —— 一天可记多条、每条带时间，支持每天/隔天/每周指定几天、按孕周或日期设起止，到点推企业微信/飞书；打卡后当天不再重复提醒。
- **深色模式**（浅色/深色/跟随系统三档，设置里切换且记住）—— 图表是 canvas 渲染、不吃 CSS 变量，单独做了 `utils/chart-theme.ts` 配色跟随；后续又修掉两处深色白条（幽灵令牌 + `.plan-item` 硬编码浅底）。
- **安全加固三处**：备份恢复/报告照片的路径越界（新增 `services/path-guard.js`，读 403、删跳过、导入整行丢弃）、恢复备份的表名注入（白名单）、推送 URL 拒绝指向内网且失败不再回显对端响应。
- **管理操作限管理员**（B2）：删数据、改推送配置、导出/备份/恢复、看日志收进 `requireAdmin` 闸门（`verify_admin_gate.js` 92 项）；家庭日常记录不受影响。**用户隔离确定不做**（家庭共用为既定设计）。
- **胎动/宫缩三家联动打通**：首页=展示+快捷记录、记录页=全部会话一条一行、统计=每天只取次数最高的那一次；「记一笔」改为追加不覆盖；计数器/计时器支持会话恢复；补临床参考判读（胎动每小时 ≥3 次、宫缩 ≥30s 且间隔 ≤5~6 分钟）。
- **首屏性能**：gzip 自建零依赖中间件 1.40MB→0.39MB。
- 发布后追加（2026-10-15，提交 `6e7290a`）：**D1「业务写入不落盘」** —— 写路由 commit 后无落盘，硬杀/OOM/断电丢最多 30 秒；修为 `markDirty` + `setImmediate` 合并落盘，30 秒定时器退居兜底，另修「异步写盘期间新写入被旧快照盖回」竞态（`_writeCount`）。回归 `probe_write_durability.js`（端到端硬杀）+ `verify_write_persist.js`（DB 单元层 + 打桩反例）。⚠️ 此修复未进 0.0.33 的 fpk，随下一版发。

## v0.0.28（2026-09-23）· 严重缺陷修复版（tag `v0.0.28`）

- 🔴 **「记录」保存失败**：日常记录 INSERT 占位符与列名数量不一致（50 vs 51），`50 values for 51 columns` —— **体重/血压/血糖/腰围等所有日常记录都写不进去，而接口返回 200**。改为「列名数组自动生成占位符 + 数量自检」。

- **检验指标 404**：`lab_result` 路由误写成 `/lab_results/:id`（下划线），统一为 `/lab-results/:id`。
- **产检建档失败**：`isValidDate` 在东八区把合法日期判为非法（本地解析 + UTC 取回回退一天）。

## v0.0.27（2026-09-04）· 统一网关迁移 + 实测修复版

本版本是动版最大的一次底层调整：整个应用从「独立 TCP 端口」模式迁移到「飞牛统一网关」模式，并彻底重建了打包发布流程。

### 统一网关迁移

前后端通信模式全面切换：`ui/config` 改为 `gatewaySocket: app.sock` + `gatewayPrefix: /app/pregnancyjournal`，后端 `server.js` 不再监听 TCP 端口，改为监听 Unix Socket（由 `FNOS_SOCKET_PATH` 指定），并增加网关前缀剥离中间件（对裸前缀访问做 301 归一）。认证层去掉了 JWT，改用网关注入的 `X-Trim-Userid` / `X-Trim-Isadmin` / `X-Trim-Username` 请求头。`cmd/main` 启动脚本按官方模板模式重写：`setsid` 会话脱离进程、启动后轮询验证 `app.sock` 就绪、`stop` 按进程路径精确清理。

### 打包流程重建与体积优化

搭建了 `build.ps1` 一键打包流水线（源码完整性校验 → 前端 assets 依赖图清理 → 生产依赖安装 → cmd 脚本编码规范化 → stage 组装 → fnpack 打包 → 解包验证）。此前打包目录里堆积了历次 Vite 构建的 1039 个冗余 assets（约 116MB），按 `index.html` 依赖图清理后仅保留 39 个可达文件，安装包从 115MB 降至 14.6MB。同时修复了多个导致安装失败的包结构问题（缺失 config/privilege、资源声明、重复目录、运行时数据混入等）。

### 实测问题修复

安装实测通过后，根据浏览器控制台反馈修复了三个功能问题：其一，`fetchActivePregnancy` 缺少 catch，无活跃孕期档案时异常直接炸掉首页（ErrorBoundary 白屏），已补置空处理；其二，`GET /checkups/custom` 被 `GET /checkups/:id` 路由遮蔽（Express 按注册顺序匹配），导致自定义产检查询报「记录不存在」、新增后列表恒为空，已为 `:id` 路由增加 UUID 校验放行具名路由；其三，相册日期用了 `dayjs().format('yyyy-MM-dd')`，小写令牌被 dayjs 当字面量输出为 `yyyy-09-Fr`，已改为大写 `YYYY-MM-DD`。另修复了 `frontend/public/config`（旧端口模式）在构建时覆盖网关配置的问题，明确其为 config 的唯一源头。

### 发布状态

- 安装包 `pregnancyjournal_v0.0.27.fpk`（14.6MB），68 项打包校验全部通过，x86-64 / ARM64 双架构，NAS 实测可安装运行
- 源码完整推送至 GitHub（xiaoke799/pregnancyjournal），Release 资产、tag、README 均已同步为修复后版本
