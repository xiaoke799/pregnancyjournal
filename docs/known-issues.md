# 已知问题（机器人回复的事实来源）

> 这个文件是 `tools/ci/issue-triage.js` 的**唯一事实来源**。机器人在 issue 里说的话，
> 只能来自这里的字段 —— 不允许它自由发挥。理由很简单：一个编造"已在 xx 版本修复"的
> 自动回复，比不回复更伤用户。
>
> 维护口径：**修好了就改状态**，别留在 `investigating` 里假装在跟进。
> 新条目取下一个未使用的编号（倒序看一眼），编号永不复用。

## KI-001 催奶食谱「鱼类 / 禽肉 / 素食谷物」分类点了没反应、只有猪蹄系列能显示

- **状态**: fixed
- **版本**: 0.0.33
- **修复提交**: 0a914da
- **关键词**: 催奶, 食谱, 猪蹄, 分类, 不显示, 食谱大全, 点了没反应
- **说明**: 分类切换用的单选组件绑定了错误的属性名（naive-ui 没有 `modelValue` 约定），
  导致点击只改内部状态、页面内容永远停在默认分类。v0.0.33 已修，并补了四层回归断言。
- **处理建议**: 升级到 0.0.33 或更高版本（fnOS 应用中心会推送更新）。升级不会影响已有数据。

## KI-002 时间显示差 8 小时（日记、相册分组、推送记录、服务端日志）

- **状态**: fixed
- **版本**: 0.0.35
- **关键词**: 时区, 8小时, 时间, 差8, UTC, 显示时间, 月份分组, 跨月, 日志时间
- **说明**: 后端按 UTC 存储、前端部分位置直接把 UTC 当本地时间显示。存储口径本身不改
  （历史数据零迁移），只修显示层：现统一走 `utils/format.ts` 的 `parseServerTime()` ——
  日记、相册（分组 / 详情 / 编辑回填 / 排序）、推送记录（`pushed_at` 本地 与 `created_at` UTC
  **分开解析**）、`info.log` 五处同源。相册「改日期」写 UTC 时间戳的写入侧问题一并修掉。
- **处理建议**: 升级到 0.0.35 或更高版本（fnOS 应用中心会推送更新）。升级不会影响已有数据。

## KI-003 上传检查报告失败（含同一条里的另外三个现象）

- **状态**: fixed
- **版本**: 0.0.28
- **关键词**: 上传, 检查报告, 失败, 传不上去, 报告上传, 找不到文件, log api
- **说明**: 原 issue 一次报了五个现象，分别处理：① 设备上传失败 —— 现为单文件 50MB、
  仅支持 JPEG/PNG/WebP/HEIC/PDF，超限或格式不符会明确报错；② NAS 取不到目录 ——
  目录浏览走路径白名单校验；③ 备份报 `log.api is not a function` —— 日志器已补齐 `api` 方法
  （缺它会抛未捕获异常，严重时整个应用白板）；④ 导出提示成功但找不到文件 ——
  产物目录可在设置页确认/指定；⑤ 微信推送 —— 属推送配置侧。
- **处理建议**: 升级到 0.0.28 或更高版本。若仍有某一项复现，请附应用版本与该子项的具体步骤
  （推送那一项还需要渠道/开关/报错信息）。

## KI-004 升级应用后数据看起来「没了」

- **状态**: fixed
- **版本**: 0.0.30 起
- **关键词**: 升级, 数据丢失, 数据没了, 记录不见, 升级后
- **说明**: 历史版本曾在升级时把可写目录与安装目录混用，导致数据看起来消失。
  现已分开：安装目录（升级会覆盖）与持久数据目录（`TRIM_PKGVAR`）互不影响。
- **处理建议**: 先**不要卸载**（卸载会清数据）。到 `TRIM_PKGVAR` 目录确认数据库文件是否还在，
  备份后升级到最新版。需要协助请贴出目录清单。

## 机器人的回复策略（改这个文件时一起看）

| 状态 | 机器人会说什么 |
|---|---|
| `fixed` | 说明已修 + 版本号 + 升级方式；请用户升级后确认，仍复现则重开 |
| `investigating` | 说明已知 + 当前进展；不承诺时间 |
| `need-info` | 列出**具体**需要补充的几项信息（不是"请提供更多信息"这种废话） |
| `wontfix` | 说明为什么不做（附既定设计口径，如"零隔离、家庭共用"） |
| 未命中任何条目 | 请求最小复现信息 + 说明会由维护者跟进；不猜原因 |

**禁止**：编造版本号、承诺修复时间、把未确认的原因说成结论。
